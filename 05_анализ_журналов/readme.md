# Задание 5. Расследование инцидента по журналам

## Сложность

Продвинутая. Решение намеренно не приведено.

## Сценарий

В этой папке находится журнал `secure.log` от условного Linux-сервера. Есть подозрение, что один из пользователей перебирал пароли по SSH, а затем получил доступ к системе. Вам нужно провести расследование только средствами терминала.

## Задание

Подготовьте `incident_report.txt`, в котором обоснованно ответьте на вопросы:

1. С каких IP-адресов были неудачные попытки входа и сколько их было для каждого адреса?
2. Какой пользователь подвергался атаке чаще всего?
3. Были ли успешные входы после серии неудачных? Укажите время, пользователя и адрес.
4. Какие IP-адреса встречаются в сообщениях о подозрительных действиях?
5. Постройте временную последовательность событий для наиболее подозрительного адреса.
6. Сформулируйте две меры защиты, которые можно применить на сервере.

## Требования к решению

- Используйте как минимум два конвейера.
- Используйте `grep` или `rg`, `awk` или `cut`, `sort`, `uniq`, `head` или `tail`.
- Не редактируйте исходный `secure.log`.
- Все числа в отчёте должны быть получены командами, а не посчитаны вручную.
- Добавьте в отчёт раздел с командами, которыми вы проверяли вывод.

## Подсказки

Сначала изучите несколько строк через `head` и `tail`, затем найдите ключевые фразы `Failed password`, `Accepted password`, `Invalid user`, `sudo` и `session opened`. Обратите внимание на структуру строки: дату, время, имя узла, процесс, пользователя и IP можно извлечь по полям.
